## Rule landed (91560eb)

A window visible at launch with no `windowPositionMask` compiles
NSWindowRect **centered on its screenRect**: About {1035,566} = center of
2560x1410 for 490x278; same for AccountStats {930,577} (2560x1410, 700x256)
and Dinosaurs {892,428}. `visibleAtLaunch="NO"` or a position mask keeps the
saved contentRect (corpus: 21 window xibs, zero exceptions). About is now
byte-identical; the MAC_CANVAS_ALLOW self-test workaround is deleted (a7cde9b).

## AccountsPreferencesView LOAD-DIFF: golden is stale, not a compiler gap

Cause: the all-goldens APV nib carries frames from a mid-edit canvas save
(root {0,121,450,259}, bottom controls at negative y) that **violates the
xib's own constraints** (add-button bottom pin archived at -102, constraint
requires -20; separators likewise). It is not a function of the current xib
(upstream == all local trees, md5 42b9358c):

- my compile of the current source == the nnw-mac-final app build,
  byte-identical (fd1304f7);
- the current-source xcodebuild app (macstudio nnw-xcode-oracle DD) == plain
  `xcrun ibtool --compile` on macstudio (a3876d58), 294/177/1432
  objects/keys/values == mine;
- the old-runs app bundles == the xtool nnw-mac5 build (cff29e84).

Load test (harness run.sh, scratch mnload13):

- golden vs my nib: LOAD-DIFF (16 lines)
- golden vs DD current-source nib: LOAD-DIFF — **the same 16 lines**
- DD vs my nib: **LOAD-IDENTICAL**

So both current-source builds load identically; only the stale golden
behaves differently. Recommendation: rebuild the golden set from the current
sources (19/35 all-goldens already differ from the DD build; 15 match).
